Un kiosko de fichaje para Holded

Una tablet compartida en la oficina. Cada persona toca su nombre para fichar entrada, salida, pausa o reanudar. Lo despliegas en tu propia cuenta de Cloudflare.

Desplegar en Cloudflare Ver el código en GitHub

Código abierto, licencia MIT. Necesitas una cuenta de Cloudflare, una de GitHub y una clave de API de Holded.

Qué hace

  • Ficha en Holded

    Entrada, salida, pausa y reanudar por empleado, con el tiempo trabajado hoy en cada fila.

  • Varias empresas en una tablet

    Cada empresa de Holded tiene su lista de empleados, sus empleados ocultos y su logo. Se cambia de una a otra con un toque.

  • Solo a quien corresponde

    Lista a los empleados con contrato vigente y sin fecha de baja. Puedes ocultar a quien no deba aparecer.

  • Pensado para pantallas táctiles

    Búsqueda por nombre, resumen de quién está dentro y fuera, y un diseño que se adapta a un iPad Mini.

Despliegue en tres pasos

  1. Pulsa el botón de despliegue

    Clona el repositorio en tu GitHub y despliega un Worker en tu cuenta de Cloudflare. Nada pasa por el Worker ni por el dominio del autor.

  2. Crea una clave de API en Holded

    Con los permisos de la tabla de abajo. Mejor una clave dedicada al kiosko.

  3. Abre el kiosko y añade la empresa

    Abre la URL del Worker en la tablet, pulsa el engranaje y pega la clave. El kiosko la valida cargando la lista de empleados.

  • API de Holded v2

El Worker sirve el frontend y atiende /api/* desde el mismo origen. La tablet envía la clave de la empresa activa en cada petición y el Worker la reenvía a Holded.

Holded permite 100 peticiones por minuto por clave. El kiosko consulta los fichajes una vez cada 2 minutos por empresa activa, y solo mientras la página está visible. Cada acción de fichaje es una sola petición.

Seguridad y límites

El Worker devuelve únicamente el id y el nombre de cada empleado, y el nombre y la URL del logo de la empresa. No devuelve IBAN, número de la Seguridad Social, salario ni dirección. Su código no guarda datos ni escribe logs. Aplica unas 120 peticiones por minuto por IP, un límite aproximado, y sirve el frontend con una Content-Security-Policy restrictiva y cabeceras de seguridad.

Lo que debes saber antes de instalarlo

  • La clave de API se guarda en el localStorage de la tablet, en texto plano y sin PIN. Cualquiera con acceso al navegador puede leerla.
  • Con el permiso team:employees.read, esa clave puede leer los registros completos de los empleados directamente en la API de Holded. Usa una clave dedicada, solo con los permisos de la tabla, y un dispositivo que controles.
  • No hay PIN por empleado. Cualquiera que tenga delante el kiosko puede fichar por cualquier otra persona.
  • La URL del kiosko no tiene control de acceso.
